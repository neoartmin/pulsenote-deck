# PulseNote PN12 Android USB

Android USB Host (CDC-ACM) application, no firmware modification required.

- Handshake: `PND:HELLO\n`, `PND:READY:2.1`, `PND:INFO:12:C3`
- Buttons: `KEY:1` … `KEY:12`
- Requires Android USB host and USB-C data connection.
- Windows firmware and software are unchanged.
- Built APK appears in Actions artifacts named PulseNote-PN12-Android-USB-APK.
- Initial build target Android 8.0+ (API 26), target API 35.

## 텍스트 매크로 (v1.3.3)

1. 장치 연결 없이 '버튼 설정'에서 PN12 / PN15 왼손 / PN15 오른손 탭 선택
2. 키 선택 → '텍스트 입력' 선택 → 이름과 넣을 문구 입력 (여러 줄 가능)
3. '장치 및 설정' → '텍스트 자동 입력 권한 설정' → 정보 확인 및 동의 → Android 접근성 설정에서 PulseNote 텍스트 매크로 서비스 활성화
4. 다른 앱에서 일반 텍스트 입력창을 선택한 다음 지정한 키 누르기

이 접근성 서비스는 **사용자가 지정한 물리 키를 누를 때** 현재 입력창의 기존 텍스트와 커서 위치를 읽고 글자를 삽입합니다. 자동으로 다른 키나 앱을 조작하지 않으며, 화면 내용 수집·저장·전송을 하지 않습니다. 암호 필드 및 PulseNote 앱 자체의 입력창은 차단합니다. 사용하지 않을 때는 Android 설정에서 끌 수 있습니다.

한글·영문·이모지·줄바꿈을 지원하나 대상 앱이 Android의 `ACTION_SET_TEXT`를 지원해야 합니다. 일부 게임/브라우저/특수 입력기에서는 입력이 제한됩니다. 서비스가 비활성화돼 있으면 텍스트 자동 삽입을 실행하지 않습니다.

**주의:** 앱의 키별 문구는 로컬 앱 설정에 평문으로 저장됩니다. 비밀번호·인증 토큰 등 민감한 텍스트는 등록하지 마세요. 해당 접근성 기능을 Google Play에 출시할 경우 별도 정책 신고·명시적 동의 등 심사가 필요합니다. 현재 APK는 GitHub Actions debug-signed 테스트 빌드입니다.

## Android v1.3.3 프로필 및 편집 단축키

- 프로필 관리의 '+ 새 프로필 만들기'는 선택된 프로필의 버튼 이름, 기능, 매크로 내용 및 색상을 PN12(12키)/PN15 L·R(각 15키)에 맞게 모두 복제합니다. 현재 프로필과 새 프로필은 이후 각각 별도로 저장됩니다. 최대 8개까지 지원합니다.
- 단축키 기능에서 `CTRL+C`, `CTRL+V`, `CTRL+X`, `CTRL+A`를 설정하면 사용자가 활성화한 접근성 서비스의 Android 편집 동작으로 실행합니다. 복사·잘라내기는 시스템 클립보드를 변경하며 붙여넣기는 그 내용을 사용합니다.
- **Windows와 동일한 범용 단축키 주입이 아닙니다.** 선택한 일반 편집 가능 입력창에서만 사용 가능하며, `CTRL+S`, `CTRL+Z`, 임의의 키 조합 또는 시스템 전역 단축키는 지원하지 않습니다. 대상 앱이 Android 접근성 액션을 지원해야 합니다.
- 줄바꿈 텍스트는 Android `ACTION_SET_TEXT`로 삽입합니다. 앱에 따라 줄바꿈이 손실되거나 이 동작 자체가 거부될 수 있으며 Windows `Shift+Enter`와 같은 물리 키 이벤트를 주입하지 않습니다. 가능한 경우 실제 결과를 재확인해 사용자에게 점검을 안내합니다.
- 기존 Android v1.3.2의 텍스트 매크로, 기존 저장 프로필, PN12/PN15 펌웨어 및 Windows 소스는 변경하지 않습니다.
- GitHub Actions에서 독립 JVM 회귀 테스트 및 Gradle 디버그 APK 컴파일을 수행합니다. Android 실기기 채팅앱/하드웨어 실측은 별도 확인이 필요합니다.

## Android v1.3.4: 아이콘·USB 자동 연결·단축키 스크롤 선택

- Windows v7.5.12와 동일한 기능 아이콘 PNG 11개가 `app/src/main/assets/action_icons`에 들어갑니다. 텍스트 입력은 Windows와 같은 파란색 T + 세 줄 아이콘을 Android 뷰로 그립니다. 개별 앱 로고와 웹사이트 favicon은 기존 Android 방식이 우선할 수 있으며, 앱 런처 아이콘은 Android 적응형 마스킹을 유지합니다.
- 단축키 기능은 기존 자유 입력란을 제거하고 **위아래로 스크롤하는 NumberPicker**에서 복사(Ctrl+C), 붙여넣기(Ctrl+V), 잘라내기(Ctrl+X), 전체 선택(Ctrl+A) 중 하나만 선택합니다. 기존에 저장된 지원 단축키 값은 그대로 표시되며 미지원 문자열은 사용자가 직접 교체할 때까지 보존됩니다.
- USB 자동 연결은 기본 켜짐입니다. 앱 화면이 활성화되어 있는 동안 USB 장치를 2.5초 간격으로 확인해 USB 연결 이벤트가 누락된 경우에도 복구합니다. 확인된 기기에는 재연결 백오프(15초)가 적용됩니다.
- **연결 종료** 버튼은 해당 앱 실행 중에만 자동 재연결을 일시정지하며 설정의 자동 연결 켜짐/꺼짐 값을 더 이상 영구적으로 변경하지 않습니다. 앱을 새로 열거나 USB를 분리했다 연결하면 자동 연결을 다시 시도합니다. 설정에서 명시적으로 자동 연결을 끈 경우 그 선택은 유지됩니다.
- 최초 USB 연결/권한 재허용은 Android의 시스템 권한 확인을 필요로 합니다. 권한 거부 또는 응답 누락 이후 같은 장치에 반복 승인 창을 띄우지 않고 사용자가 'USB 연결'을 눌러 다시 시도할 수 있습니다.
- 이 변경은 펌웨어의 CDC 프로토콜이나 프로필 형식, Windows PC 앱을 변경하지 않습니다.
- 실물 Android 기기, USB OTG 케이블, 실제 채팅 앱별 자동 동작은 별도 검증 대상입니다.

## Android v1.3.5: 권한 설정 통합 · 스크린샷

- 앱 최초 실행 시 '필요한 권한 설정' 버튼을 표시합니다. '장치 및 설정 → 권한 및 직접 실행'에서 언제든 다시 실행할 수 있습니다.
- 하나의 시작 버튼으로 **알림 → 다른 앱 위에 표시 → 편집 단축키용 접근성(선택 사항)**을 순서대로 안내합니다. 실제 승인/거부는 Android 시스템에서 각각 직접 결정합니다.
- USB 장치가 연결돼 있으면 마지막 단계에서 USB 권한 요청을 안내합니다. 처음 연결한 USB 장치는 Android의 시스템 팝업에서 승인해야 하며, 케이블이 없는 상태에서는 미리 승인할 수 없습니다.
- **화면 캡처는 최초 실행 시 한 번 허용할 수 있는 권한이 아닙니다.** Android 14 이상에서 캡처 세션을 시작할 때마다 시스템 화면 공유 동의를 받아야 합니다. 거부하면 촬영/저장을 하지 않습니다.
- 텍스트 매크로 키 종류 11번은 '화면 캡처'로 교체됐습니다. 기존 프로필의 종류 11 키는 자동으로 캡처 버튼이 되며, 과거 텍스트 데이터는 설정 보존을 위해 삭제하지 않지만 더 이상 실행에 사용하지 않습니다.
- PN12/PN15의 캡처 키를 누르면 앱이 화면에 있을 경우 즉시 Android 시스템 승인 창을 띄웁니다. 앱이 백그라운드에 있으면 알림을 누른 뒤 승인을 진행합니다. 알림 권한이 없으면 캡처를 시작하지 못할 수 있습니다.
- 승인을 받은 화면 한 장만 PNG로 캡처하여 Android 10 이상에서는 '사진/PulseNote Deck'에 저장합니다. Android 8~9에서는 앱 전용 외부 사진 폴더에 저장합니다.
- 복사·붙여넣기 등 편집 단축키는 **별도 선택형 접근성 기능**으로 유지됩니다. 스크린샷은 접근성 허용 없이 사용 가능합니다.
- PC의 기존 텍스트 입력 및 캡처 외 기능과 펌웨어의 CDC 프로토콜은 유지됩니다.
- Android 기기별 화면 공유, USB 연결/권한 흐름, 백그라운드 실행은 실제 기기에서 별도 검증이 필요합니다.

## v1.3.7 · Google Play 프로텍트 설치 차단 위험 감소

Google Play 프로텍트는 외부에서 설치한 APK가 화면 정보·기기 조작 권한 등을 요청할 때 설치를 차단할 수 있습니다. 설치 차단을 우회하기 위해 Play 프로텍트를 해제하지 마세요.

이번 릴리스는 두 가지 설치판을 제공합니다.

- **기본 설치판(권장)**: `PulseNote_PN12_PN15_Android_v1.3.7.apk`. Android manifest에서 `BIND_ACCESSIBILITY_SERVICE` 접근성 서비스를 제거하고 `SYSTEM_ALERT_WINDOW`(다른 앱 위 표시) 권한도 제거했습니다. 기존 PN12·PN15 USB 통신, 버튼·프로필 설정, 볼륨·미디어 제어, 웹사이트/앱 실행 요청, 화면 캡처 및 캡처 시 시스템 승인 절차를 유지합니다. 편집 단축키(Ctrl+C/V/X/A) 및 화면 위 표시 기반 백그라운드 직접 실행은 지원하지 않습니다.
- **확장 설치판(선택)**: `PulseNote_PN12_PN15_Android_v1.3.7_Extended.apk`. 기존 v1.3.6의 선택형 접근성 편집 단축키와 화면 위 표시를 유지합니다. Play 프로텍트에서 계속 설치 차단할 수 있으므로 보안 경고를 무시하거나 보호 기능을 해제하지 마세요.

두 APK는 같은 `applicationId`를 사용하므로 동시에 설치할 수 없습니다. APK는 CI의 **디버그 서명** 빌드이며 Android 보안 검사를 통과한다고 보장하지 않습니다. 기존 앱과 서명이 일치하지 않는 경우 덮어쓰기 설치는 실패할 수 있습니다. 운영 배포에는 소유자가 관리하는 고정 릴리스 서명과 공식 배포 심사가 별도로 필요합니다.

빌드 검증: `assembleStandardDebug assembleExtendedDebug`와 `tools/check_android_permissions.py`로 최종 병합된 기본 설치판의 manifest에 접근성 서비스·오버레이 권한이 실제로 없는지 검사합니다. 기기에서 Play 프로텍트 설치 여부와 실행 기능은 별도 확인이 필요합니다.

## Android v1.3.8 · 캡처 대기 모드 (승인 1회 후 반복 캡처)

- 캡처 키의 최초 실행 시 Android 화면 공유 동의를 요청하며, 승인하면 **포그라운드 MediaProjection 세션 하나와 VirtualDisplay 하나**를 유지합니다.
- 첫 승인 직후에는 첫 캡처를 저장합니다. 이후 PN12/PN15 캡처 키를 여러 번 눌러도 **같은 세션의 최근 화면 프레임**을 각각 PNG로 저장하므로 새 승인창을 반복 표시하지 않습니다. USB 연결/프로필/기존 스크린샷 아이콘은 그대로입니다.
- '장치 및 설정 → 캡처 대기 모드 시작'을 누르면 **즉시 사진을 저장하지 않고** 대기 모드만 켤 수도 있습니다.
- 활성 상태에서는 Android의 화면 공유 표시와 **지속 알림**이 보입니다. 알림의 **캡처 모드 종료** 또는 앱 내 종료 버튼으로 공유를 직접 끝낼 수 있습니다. 종료·시스템 중단·화면 잠금 등으로 세션이 없어지면 다음 사용 시 다시 동의해야 합니다.
- 세션이 활성화된 동안 Android 화면 내용이 프로젝션 시스템으로 지속 전달됩니다. 앱은 마지막 프레임 하나만 메모리에 유지하며 **사용자가 캡처 키를 누를 때에만** PNG를 저장합니다. 화면을 외부 서버로 전송하지 않습니다. 배터리·메모리 사용이 늘어날 수 있습니다.
- Android 14 이상에서 화면 캡처 동의 토큰은 세션당 1회만 사용해야 하므로 동일 MediaProjection에 `createVirtualDisplay()`를 한 번만 호출하고, 방향 전환 시 새 세션을 만들지 않고 기존 VirtualDisplay와 Surface 크기를 조절합니다.
- 첫 승인은 앱 화면에서만 시작할 수 있습니다. 앱을 벗어난 상태에서 세션이 꺼져 있으면 기존 방식대로 알림을 눌러 승인하고, 켜져 있으면 버튼으로 바로 저장합니다.
- 기본 설치판(권장)은 접근성 서비스/오버레이 권한을 추가하지 않습니다. 확장판에도 동일 캡처 동작을 적용합니다.
- Android 실기기에서 화면 공유 승인, 회전, 앱 전환, 장시간 유지, 물리 버튼 반복 캡처와 PNG 저장을 검증해야 합니다. CI 컴파일 성공만으로 정상 동작을 보장할 수 없습니다.

## Android v1.3.9 · 기본 설치판 접근성 관련 구성 제거

기본 설치판(Standard)에서는 Android 접근성 기능을 단순히 비활성화하는 데 그치지 않고 **APK의 접근성 서비스 구현, 접근성 설정 XML·문구 리소스, 텍스트 입력 단축키 처리 코드, 기능 선택 버튼, 최초 권한 안내**를 제외합니다. 편집 단축키와 접근성 설정은 확장판(Extended)에만 남습니다.

- 일반용: PN12·PN15 USB 자동 연결, 프로필, 볼륨, 미디어, 프로그램/웹사이트, 폴더, 캡처 대기 모드(첫 승인 후 반복 PNG 저장) 유지.
- 기존 키가 편집 단축키(내부 기능 번호 9)로 설정된 경우 일반용에서는 '기능 없음'으로 표시하고 실행하지 않습니다. **설정 원본은 삭제·변경하지 않습니다.** 확장판으로 돌아가면 기존 할당을 복구해 사용할 수 있습니다.
- 새 프로필을 만들 때에도 원래 할당 데이터를 보존하므로 확장판 전환 시 유실되지 않습니다. 일반용에서는 새 단축키 할당을 생성할 수 없습니다.
- 확장판: 기존 접근성 서비스 및 편집 단축키 스크롤 선택을 그대로 유지합니다. 민감 권한을 요구하는 확장판은 Play 프로텍트에 의해 설치 차단될 수 있습니다.
- 일반용에도 USB 장치 권한, 알림 권한 및 **최초 화면 공유 승인**은 해당 기능을 사용하기 위한 Android 시스템 단계로 남습니다. 이 권한들은 접근성 서비스가 아닙니다.
- `tools/check_android_permissions.py`: 최종 병합된 일반용 매니페스트에서 접근성 서비스/화면 위 표시 권한 부재를 검사합니다.
- `tools/check_android_standard_clean.py`: APK의 DEX/리소스에 접근성 구현, 편집 단축키 파서, 이전 텍스트 매크로 구현 파일이 포함되지 않았는지 검사합니다. 확장판에는 해당 구현이 남아 있어야 합니다.
- 기본/확장 APK는 같은 applicationId를 쓰므로 동시 설치가 불가능합니다. 기존 설치판과 서명이 맞지 않으면 덮어쓰기 설치가 제한됩니다. Play 프로텍트 통과 자체는 보장할 수 없으며 보호 기능 해제를 권장하지 않습니다.

## Android v1.4.0 · 추가 권한 없는 버튼 기능 4종

기존 PN12·PN15의 키 설정 ID 0~11은 보존하고, 일반판과 확장판에 다음 기능을 추가했습니다.

| 기능 | 액션 ID | 실행 방식 |
| --- | --- | --- |
| 문구 복사 | 12 | 입력한 한글·줄바꿈·이모지 포함 최대 4096 UTF-16 코드 단위를 클립보드에 복사합니다. 자동 붙여넣기나 키보드 주입은 하지 않습니다. |
| 설정 바로가기 | 13 | 스크롤 선택 목록에서 Wi-Fi, 블루투스, 디스플레이, 소리, 절전, 전체 설정 화면을 지정해 엽니다. 설정값을 자동 변경하지 않습니다. |
| 타이머 열기 | 14 | Android 시계 앱의 타이머 화면을 엽니다. 타이머 시작/추가는 사용자가 직접 합니다. |
| 알람 열기 | 15 | Android 시계 앱의 알람 화면을 엽니다. 알람 생성/변경은 사용자가 직접 합니다. |

- 새 액션은 접근성·오버레이·카메라·저장소 등 **추가 Android 권한 선언이 필요하지 않습니다**. 기존 USB 연결 권한은 장치 접속 시 필요합니다.
- 앱이 백그라운드에 있다면 설정 및 시계 앱 실행은 시스템 정책에 따라 알림을 탭해야 할 수 있습니다. 알림 권한을 거부한 경우 일부 백그라운드 열기가 제한됩니다.
- 클립보드 복사는 기존 내용을 덮어쓰고 Android 시스템/키보드 앱에서 붙여넣을 수 있으므로, 비밀번호나 민감한 문구는 저장하지 마세요. Android 13 이상에서는 클립보드 미리보기에 민감 콘텐츠 표시를 숨기도록 마킹합니다.
- 설정과 타이머/알람 인텐트는 제조사 앱에서 지원하지 않을 수 있습니다. 실패 시 메시지를 표시하며 시스템 설정 값을 임의 변경하지 않습니다.
- 4개 아이콘은 512×512 PNG로 제작하여 기존 Windows 아이콘 자산과 공유합니다.
- 사용자 설정 및 모델별 프로필, USB 핸들링, 캡처 세션(첫 승인 후 반복 저장), Android 기본판의 접근성 제외 상태를 유지합니다.
- 자동 테스트는 로직·PNG 규격·두 APK 컴파일을 검증합니다. 실제 기기에서 백그라운드 실행/클립보드 동작은 별도 확인해야 합니다.

## Android v1.4.1 · 고유 기능 추가 (기본판/확장판)

- **웹 검색**: `google|검색어`, `naver|검색어`, `youtube|검색어`. 검색어를 URL 인코딩한 검색결과를 브라우저에서 엽니다. 기존 고정 URL 버튼과 별도 기능입니다.
- **이메일 작성**: `받는사람|제목|본문`을 입력하면 설치된 메일 앱의 작성 화면을 엽니다. **자동 전송하지 않습니다.**
- **QR코드 생성**: 최대 900바이트 UTF-8 내용으로 **ZXing 3.5.4**를 사용해 네트워크 연결 없이 QR 이미지를 표시합니다. PNG 저장은 Android 파일 생성 화면을 열어 사용자가 위치를 직접 정합니다. 카메라/저장소 권한을 요청하지 않습니다.
- **연속 동작**: `2,wait:250,4`처럼 같은 모델·좌우 방향의 **현재 프로필에 설정된 다른 키**를 실행합니다. 최대 8단계, wait:0~1000ms, 자기 키/다른 연속 동작 키 참조 금지. 연속 동작은 전용 백그라운드 직렬 작업에서 처리하여 앱 UI를 차단하지 않습니다. 실행 상태는 반환되는 메시지/로그에서 확인하며, Android가 제한하는 활동 자동 실행은 기존과 동일하게 알림 승인이 필요합니다.
- **문구 공유**: 지정 문구를 Android 공유 시트로 전달하고 사용자가 대상 앱을 선택합니다. 자동 전송하지 않습니다.

기존 기능 번호 0~15를 유지하고 16~20만 추가합니다. 일반판에는 **접근성·오버레이 추가 권한이 없으며**, 기존 PN12/PN15 프로필·USB 자동 연결·캡처 대기 모드는 유지됩니다. 외부 앱을 여는 기능은 Android 백그라운드 시작 제한의 영향을 받을 수 있습니다.

기존과 겹치는 단순 계산기·카메라·지도 실행, 홈 화면 바로가기 등의 별도 버튼은 추가하지 않았습니다. 앱 열기/웹사이트/단축키 기능으로 구현 가능하거나 Android 무접근성 구조에서 안정적으로 제공할 수 없기 때문입니다. QR는 `com.google.zxing:core:3.5.4` 의존성을 포함합니다.

Windows v7.5.16에서도 웹 검색·이메일 작성·오프라인 QR·연속 동작을 지원하며, Windows 고유 기능인 클립보드 기록과 창 제어는 Windows 앱에서 제공합니다. Windows 공유 메뉴는 별도 WinRT 연동을 요구하므로 이번 일반 Win32 릴리스에 포함하지 않았습니다.

CI는 JVM 매크로 검증, 이미지 자산 동일성, Android 기본/확장 APK 컴파일과 최종 권한 구성을 확인합니다. 실기기 확인 전까지는 호환성을 보장하지 않습니다.
